# Software-Test-Automation-QA-Project
For SNHU class Software Test, Automation QA


## How can I ensure that my code, program, or software is functional and secure?
  I can ensure my code, program, or software is functional and secure by taking time to properly plan and test it. Through planning, I can carefully design an overall plan of my system and review it for errors before any code is written. When code for the system is written, I can test it to determine the number of lines of code reached and if they produced the expected output. 

## How do I interpret user needs and incorporate them into a program?
  When interpreting user needs, I first try to understand the context of the need. For instance, if I were designing a replacement system for a company, I would try to see or know more about the original system to know where the user need comes from. From that context I can determine if the user need is too high-level and if it needs to be broken down into multiple user needs. Then I rewrite the user need as a requirement for the system which can then be easily incorporated into the system design.

## How do I approach designing software?
  I approach designing software by breaking down requirements into parts and then combining those parts into manageable and associated groups. For instance, in this project the task object had to contain an ID that was unique, no larger than 10 characters, non-updatable, and not null. This requirement could be broken down into parts and sorted into two groups. The first group being requirements related to the task object itself (object ID field cannot be null or more than 10 characters and cannot be updated). The second group in this case is composed of one part that must be implemented using an outside class or system (each object ID must be unique).
